# 知识库使用流程

更新日期：2026-11-17（对应代码版本 0.3.22 草稿）

本文按界面操作顺序说明如何在知识库中导入文档、阅读、抽取本体、发布到图谱以及使用知识助手。
实现细节（解析规则、检索打分、质量报告规则、存储与权限）见[知识库架构](../../architecture/knowledge/knowledge-base.md)，本文不重复。

## 1. 入口

知识库页面只对管理员显示，有两个入口，打开的是同一个页面：

- 数据中心左侧导航“数据探索”分组下的“知识库”（`/data-center/knowledge`）。
- 后台“数据与集成”分组下的“知识库”（`/admin/knowledge`）。

页面分为三栏：左侧是文档列表和“导入文档”区域，中间是文档阅读区，右侧是检查栏（大纲、关联、助手）。底部状态栏显示文档总数以及已索引、待抽取、已发布的数量。

如果列表为空，可以先导入演示文档，见[演示知识资产](../../operations/demo-knowledge-assets.md)。

## 2. 导入文档

把文件拖入左侧“导入文档”区域或点击后选择文件。支持 Markdown、文本、Word（`.docx`）、Excel、PDF 和常见图片格式；扫描版 PDF 和图片会走 OCR。各类型的转换方式和限制见[知识库架构的“上传与解析”](../../architecture/knowledge/knowledge-base.md#3-上传与解析)。

导入在请求内同步完成。成功后页面提示“资料已进入知识库”，自动选中新文档，并在右侧“助手”中给出本体抽取准备建议。

需要知道的限制：

- 页面上传时固定使用“企业”范围和 `knowledge-admin` 作为所有者，界面不能修改；这两个字段目前也不影响谁能看到文档。
- Excel 只导入每个工作表的列名和前 10 行，不是全量数据。
- 页面没有 OCR 结果查看和修正入口。需要修正识别错误时，只能调用 `/api/v1/knowledge/documents/{id}/ocr` 系列接口，见 [API 参考](../../development/api-reference.md)。
- 页面没有删除文档的操作。

## 3. 阅读文档

在左侧选中文档后，中间区域顶部可以切换四种视图：

| 视图 | 内容 |
| --- | --- |
| 阅读 | 渲染后的 Markdown 正文 |
| 源码 | Markdown 原文 |
| 关联 | 已写入的关联对象卡片，显示对象编号、置信度和证据位置 |
| 图谱 | 当前文档已发布的抽取结果组成的图，数据来自图谱资产接口 |

右侧检查栏的“大纲”列出文档标题，点击可跳转，下方显示更新时间、关联对象数和字符数；“关联”列出已确认的关联对象，并可一键切到图谱视图。

“搜索工作空间”按钮（Ctrl 或 ⌘ 加 K）打开的是全局搜索，不是知识库检索。

## 4. 抽取、审核与发布

在右侧切到“助手”，第一张卡片是“AI 本体抽取准备”，显示系统判断的文档类型、领域、行数和建议动作。

1. 点击“开始本体抽取”。抽取使用固定规则，不调用大模型，几秒内完成，页面会自动切到“关联”视图。卡片下方显示通用对象、领域映射、关系三个数量，实体列表（名称、类型、证据位置），以及质量检查结论。
2. 如有需要，点击“审核通过”。审核会重新运行质量检查，但不是发布的前提。
3. 点击“发布到图谱”。如果质量检查发现阻断问题（目前只有“没有抽出任何实体”这一种），按钮不可用。发布后页面切到“图谱”视图。底部状态栏把所有带关联对象的文档都计为“已发布”，因此演示种子文档即使没有执行过发布也会计入。

发布会做三件事：把实体和关系写入 Neo4j（Neo4j 不可用时跳过，但不影响其余步骤），把每个实体写成本文档的关联对象，把实体和关系写入本体候选，供数据中心“对象与关系”中审核。

使用时注意：

- 抽取出的关系都是“相邻两个实体相关”（`RELATED_TO`），不表示真实的业务关系，需要人工判断。
- 发布产生的图谱节点是独立的新节点，不会和已有的设备、物料、供应商主数据合并，也没有手工绑定到主数据的界面。
- 切换到其他文档再切回时，上一次的抽取结果不会重新显示；需要再次点击“开始本体抽取”，这会生成新的任务。
- 同一文档重复发布，会写入重复的关联对象。

“知识助手”卡片中的“抽取结果”和“发布清单”标签页展示的是同一次抽取的实体和关系，“发布清单”里的按钮与“发布到图谱”效果相同，但要求至少有一条关系。

## 5. 知识助手问答

“知识助手”卡片的“对话”标签用于针对当前文档提问：

- 选中文档时会自动打开或恢复该文档的会话，每个用户、每篇文档各有一个会话，刷新页面后历史消息仍在。
- 回答由 AI 设置中配置的模型生成，并引用检索到的分块作为证据。AI 被关闭或当前用户没有问答权限时，会提示服务暂不可用。
- 检索对中文关键词效果很差，直接问编号（如 `MB-7781`、`SMT-03`、`QE-20260521-001`）更可靠；问“总结这篇文档”这类问题时，系统会带上整篇文档的内容。

“文档属性”标签显示文档名、类型和状态。

## 6. 在质量影响页面查看知识

后台“质量影响与时间线”（`/admin/quality-impact`，实验功能）以图的形式展示质量事件影响到的物料批次、供应商、工单、设备和订单。选中节点时，右侧会尝试显示相关知识卡片，但默认配置下知识卡片接口返回空列表，所以这块通常为空。该页面依赖 Neo4j 中的业务对象图，准备方法见[图谱集成](../../architecture/knowledge/graph.md#4-数据写入途径)。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 左侧没有知识库入口 | 当前账号不是管理员 |
| 文档列表为空 | 当前租户还没有文档；导入文件或运行演示种子脚本（只写入租户 1） |
| 发布后“图谱”视图有数据，但 Neo4j 中查不到 | 发布时 Neo4j 不可用或超时，图谱写入被跳过；图谱视图的数据来自抽取任务本身 |
| 问答回答与问题无关 | 中文关键词检索不可靠，改用编号提问，或在问题中带上“总结”“内容”让系统读取整篇文档 |
| 后端重启后部分 OCR 修正接口返回 404 | 这类接口只处理当前进程内的文档，见[知识库架构](../../architecture/knowledge/knowledge-base.md#22-进程内状态与数据库的关系) |
