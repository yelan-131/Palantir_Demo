# 业务表单配置指南：从配置到发布

更新日期：2026-11-17（对应代码版本 0.3.22 草稿）

本文面向业务管理员、实施人员和验收人员，按实际操作顺序说明如何在“应用配置”中建立一张业务表单、设计填写规则和审批流程、把它放进页面和应用菜单、授予角色权限并完成验收。运行时数据如何保存、权限如何判定，见[表单运行逻辑](form-interaction-logic.md)；不依赖现有源码、从零实现同类系统的规格见[从零编写业务表单系统](../../development/business-form-spec/from-scratch.md)。

文中以“设备告警处理单”为例，字段、角色和流程都是示例，需要按实际业务调整。

## 1. 整体流程

一张能被业务人员使用的表单，需要依次完成以下配置。除第 7 步外，所有入口都在“应用配置”下，并且仅管理员可见：

1. 在“业务数据”中新建表单，建立字段结构。
2. 进入表单设计器，设计填写布局和字段规则。
3. 在设计器的“流程与审批”中配置审批（不需要审批可跳过）。
4. 试填、检查并发布表单。
5. 在“页面设计”中新建页面，添加“业务列表”组件，配置列表筛选、列表显示和工具栏，发布页面。
6. 在“应用与菜单”中把已发布的页面加入应用菜单，发布应用。
7. 在“后台设置 → 组织、身份与权限”中为业务角色授予表单权限。
8. 用实际业务账号验收。

这里有三类容易混淆的内容。设计器中的“保存草稿”保存的是表单配置；业务页面中的“保存草稿”保存的是一条尚未提交的业务单据；“发布”让配置对业务页面生效，而“提交审批”是业务人员提交一条具体单据。另外，**表单和页面分别发布**：表单发布不会发布页面，页面发布也不会发布表单。

## 2. 配置前准备

开始前确认自己是管理员。“业务数据”“页面设计”“应用与菜单”和表单发布接口都要求管理员身份。

建议先整理以下信息：

- 表单名称、编码和用途说明，以及要放进哪个应用、哪个菜单。
- 业务字段的名称、类型、是否必填、默认值和选项来源。
- 使用表单的角色，例如告警发起人、处理人、主管，以及每个角色能做什么。
- 是否需要审批，各审批节点由谁处理。
- 需要引用的数据字典、基础档案、人员组织或其他业务表单。

例如，“设备告警处理单”用于登记设备异常、指定处理人、补充处理结论，并由主管审核。

## 3. 新建业务表单

1. 打开“应用配置 → 业务数据”，点击页头的“新增表单”。左侧“表单”列表中会出现一张名为“新建表单”的本地草稿，卡片标注“业务表单”。
2. 在右侧“表单属性与数据来源”中填写基本信息：表单名称（例如“设备告警处理单”）、表单编码（例如 `equipment-alert`）和说明。表单编码保存后不可修改，名称可以随时调整。
3. 点击“保存草稿”。“创建人”和“数据来源”在保存后由系统自动填写。

新建的业务表单使用由表单引擎托管的物理表保存数据。物理表和新增字段对应的列在保存时就可能创建，所以不要认为发布前的所有结构变更都不会触及数据库；字段归档后物理列也不会删除。存储方式的说明见[表单引擎](../../architecture/low-code/forms.md)。

## 4. 建立字段结构

在“业务数据”右侧的“字段结构”区块中点击“新增字段”，在抽屉中填写：

- 字段名称：显示给用户的名称。
- 字段编码：系统内的稳定标识，创建后固定，不能修改。
- 字段类型：文本、长文本、布尔、明细 / JSON、整数、小数、日期、日期时间、单选、人员、附件。选择“单选”时需要填写“单选选项”。
- 按类型提供的其他设置，例如最大长度（字节）、可搜索、可排序。

必填、列表显示和展示布局不在这里配置，而是在表单设计中配置。

本例可以建立以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 告警编号 | 文本 | 在表单设计中配置编码规则自动生成 |
| 告警标题 | 文本 | 勾选“可搜索” |
| 设备 | 文本 | 在表单设计中把选项来源设为设备基础档案 |
| 告警等级 | 单选 | 选项为普通、重要、严重 |
| 责任人 | 人员 | |
| 发生时间 | 日期时间 | 勾选“可排序” |
| 处理结论 | 长文本 | |
| 附件证据 | 附件 | |

字段类型要与实际值一致：数量和金额使用整数或小数，时间使用日期或日期时间，有限的状态集合使用单选。已经有业务数据后再修改类型或收紧约束，发布时会触发影响检查（见第 8 节）。

## 5. 设计填写表单

在“业务数据”中选中表单，点击表头的“进入设计”，打开表单设计器。从“业务数据”进入的设计器只有两个页签：“表单设计”和“流程与审批”。列表、筛选和组件访问权限不在这里配置，而是由组件页面中的业务列表负责（见第 9 节）。

> 从组件页面右键“业务配置”打开的是同一个设计器的内嵌形式，页签名称为“填写表单”和“流程与审批”，左侧面板显示为“字段与布局”“添加控件”“表单字段”，发布按钮为“发布更改”，预览按钮为“试填表单”。下文以从“业务数据”进入的名称为准。

### 5.1 布局和控件

在左侧的“控件库”中点击或拖入控件和布局容器，在“字段库”中把已有字段加入画布。选中画布上的控件后，在右侧属性区设置标题、宽度、提示文字和填写规则。

按业务步骤对字段分组，例如“告警信息”“处理信息”“审核信息”。同一字段只能绑定一个输入控件；复制控件后要检查是否产生了重复绑定。纯布局容器不需要绑定字段。

### 5.2 选项来源

选择类控件的“来源类型”可以是静态选项、数据字典、基础档案、业务表单、用户组织或外部接口。数据字典和基础档案在“后台设置 → 字典与基础档案”中维护；外部接口来自数据中心登记的接口数据源（见[数据接入与连接器](../../architecture/integration.md)）。

配置后需要检查：单选和多选与展示方式是否匹配；选项值是否重复；来源能否返回候选项；默认值是否在候选项中；多选的数量限制是否与默认选中数量冲突。静态选项建议使用稳定编码作为选项值、中文作为显示标签，以后只改标签，不改已被历史记录使用的值。

### 5.3 默认值、编码规则和计算

- 默认值可以是固定值，也可以按规则生成。可以为默认值添加条件，只有全部条件满足时才预填；已经填写的内容不会被默认值覆盖。
- 编码规则由多个编码段组成，编码段可以是固定文本、日期、流水号、组织编码、档案编码或字段取值，流水号可设置重置周期、起始值和步长。例如把“告警编号”设计为 `AL` + 年月 + 三位流水号。试填中的编码只是预览，唯一性以正式保存时为准。
- 计算规则支持数值算术、文本拼接和按条件取值，复杂表达式可以使用高级公式。需要检查引用字段、结果类型，以及空值、零值和小数的处理方式。

### 5.4 校验和字段状态

按业务设置必填、只读、隐藏、格式、长度、数值范围和唯一性。不要把一个没有可靠赋值来源的字段同时设为隐藏和必填。本例中，“告警编号”由系统生成，业务人员只读；“处理结论”在处理节点要求填写，需要结合第 6 节的节点字段权限一起配置。

## 6. 配置流程与审批

不需要审批的表单可以跳过本节。需要审批时，打开设计器的“流程与审批”页签：

1. 从节点库添加“审批任务”节点，用连线把“开始事件”、审批节点和“结束事件”连起来。本例可以采用“开始 → 处理人处理 → 主管审核 → 结束”。
2. 在每个审批节点的“处理人规则”中添加处理对象。对象类型可以是角色、用户、组织、表单字段、部门负责人或发起人上级；审批方式可以是单人、或签或会签。
3. 需要分支时添加“条件网关”，在连线的“连线规则”中设置条件规则（按表单字段比较）、优先级和默认路径，确保每一种字段取值都有后续路径。
4. 在审批节点的“节点字段权限”中设置各字段在该节点的可见、可填和必填。
5. 在画布属性的“表单触发”中确认启用的触发动作，例如“提交表单”。
6. 需要把数据推送到其他表单或外部系统时，添加“自动任务”节点并开启“数据下发”，推送方式可以是创建站内表单草稿、调用 API 或 Webhook。

节点库中并非所有节点都能运行。可执行的节点是开始事件、结束事件、审批任务、自动任务、抄送任务和条件网关。“并行网关”和“汇聚网关”可以画出，但发布流程时会被拒绝，会签或或签应通过同一节点的多个审批组实现。定时事件、消息事件、脚本任务、包容网关、子流程等节点目前不可执行。

审批人在审批时只能填写审批意见，不能修改业务字段；驳回时必须填写意见。节点字段权限目前主要控制记录在审批过程中对各角色是否可见。

如果已有流程加载失败，设计器会阻止保存和发布，以免覆盖原流程。应先解决加载问题再继续。

## 7. 保存草稿、试填和检查

1. 点击工具栏的“保存草稿”。保存失败时修改仍留在编辑器中，修复问题后重新保存即可。离开设计器时如果有未保存修改，会提示“当前有未保存修改”，可以选择“放弃并离开”或“继续编辑”。
2. 点击“预览”打开试填抽屉，抽屉标注“当前草稿”。可以切换预览角色和流程节点，检查字段顺序、必填、只读、隐藏、默认值和选项来源是否符合预期。
3. 点击“检查必填项”。这一检查只验证必填和选择数量；数值、格式和字节限制以业务页面实际保存时的校验为准。试填内容不会保存为业务记录。

## 8. 发布表单

### 8.1 从设计器发布

点击“发布配置”或组件属性标题栏的“发布更改”。系统保存草稿后直接提交发布。新增必填字段允许历史记录保留空值，发布后新录入仍须填写。发布失败时会提示原因，草稿可继续编辑。常见失败原因及处理方法如下。

- 把可选字段改为必填，但历史数据有空值：先补齐空值，再重新检查。
- 字段类型与历史值不兼容：先确定数据转换方案并完成处理，再发布。
- 删除了历史记录仍在使用的选项值：保留旧值，或先迁移历史值。

发布成功后会生成新的表单版本快照。配置了审批流程时，流程定义与触发绑定和表单版本同时生效。

### 8.2 从业务数据页发布

“业务数据”属性面板中也有发布按钮：草稿状态显示“保存草稿”“发布”“删除草稿”，已发布状态显示“保存变更”“发布更新”，以及“更多操作”中的“复制为草稿”和“停用”，已停用状态显示“保存配置”和“启用”。字段数为 0 时发布会提示“请先进入设计添加字段，再发布”。

这里的“发布”只发布表单版本，不会发布设计器中的流程草稿。配置了流程与审批时，请使用设计器中的“发布配置”。

## 9. 在组件页面中展示表单

业务人员通过组件页面使用表单。组件页面有自己的草稿和版本，与表单的发布互不影响。

### 9.1 新建页面并添加业务列表

1. 打开“应用配置 → 页面设计”，点击“新建页面”，填写“页面名称”后点击“创建并设计”。
2. 在页面设置的“添加组件”中添加“业务列表”。可添加的组件还有“指标卡”和“分组图表”。
3. 选中业务列表，在“数据”页签的“数据来源”中选择业务来源，即第 8 节发布的表单。业务来源统一在“应用配置 → 业务数据”中管理。

### 9.2 配置列表筛选

0.3.22 起，列表筛选在业务列表的“数据”页签中配置，不再使用独立的筛选组件：

1. 在“列表筛选”中打开“启用列表筛选”，表格上方会显示查询条件，条件来自当前列表的业务来源。
2. 每个列表至少有一个筛选方案。可以“新增筛选方案”（复制当前方案，最多 12 个），也可以删除当前方案（至少保留一个）。每个方案有方案名称和适用对象，适用对象可以是角色、用户或用户组/组织。
3. 在“筛选区域”中设置“默认行数”（自动，或 1 到 12 行，默认 2 行）和“每行筛选项”（1 到 6 个，默认 4 个）。开启“关键词搜索”时，关键词框占一个位置，按来源表单中设为可搜索的字段查找记录。窄屏下每行最多显示两个筛选项。
4. 勾选筛选字段，并为每个字段选择选择方式：沿用来源、下拉单选、单选按钮、下拉多选或多选框。
5. 在“查询与重置按钮”中设置查询按钮的查询方式（点击查询，或条件变化自动查询）和按钮文字，以及重置按钮的重置行为（恢复来源默认值，或清空所有条件）和按钮文字。查询和重置按钮放在最后一行筛选字段的下方，并随当前方案的适用对象显示。

页面设计中已不再提供独立筛选组件的新增入口。旧页面中保留的独立筛选组件会显示“旧版独立筛选”提示；需要移除它时，先在业务列表的“数据 → 列表筛选”中配置所需条件。编辑旧页面时，同一来源且只服务一个列表的旧筛选会自动合并到该列表。

### 9.3 配置列表显示、工具栏和组件访问

- “列表显示”：按权限组设置可看和可排序的列、默认排序、排序方向、每页条数和空数据提示。多个权限组同时匹配时，按权限组顺序取第一个有效配置。
- “基本”页签中的工具栏按钮：新增 / 填写申请、刷新、批量导入、导出、禁用、删除。按钮是否可用同时受业务权限、记录状态和审批规则约束。
- 列表交互：行点击行为和记录选择方式；记录选择只作用于当前页。
- 组件访问：用权限组限制哪些用户能看到该组件。
- 页面设置的“权限”：设置允许访问页面的角色，不设置时不限制。

本例建议：列表显示告警编号、标题、设备、等级、责任人和发生时间，按发生时间倒序；筛选条件为告警等级、设备、责任人和发生时间；把告警标题设为关键词搜索字段。

页面上的组件右键菜单中，“业务配置”提供“字段与录入”和“流程与审批”两个入口，会打开来源表单的内嵌设计器。在这里修改后需要点击“发布更改”发布表单，它不会随页面一起发布。

### 9.4 发布页面

点击“保存草稿”，然后点击“创建首个版本”（已发布过的页面显示“发布新版本”），在“发布页面”中“确认发布”。页面列表中会显示“已发布 · vN”。页面工具栏中的“页面版本管理”可以查看历史版本，并把某个版本“恢复到草稿”。

如果业务列表的来源表单尚未发布，页面上不会有数据，旧版筛选组件会提示“请先发布来源业务表单”。

## 10. 加入应用菜单

1. 打开“应用配置 → 应用与菜单”。没有合适的应用时点击“新增应用”，在应用属性中填写应用名称、应用编码、应用图标和应用说明，在“应用访问”中选择可访问的角色，然后“保存草稿”。应用保存后才能添加页面。
2. 在左侧“已发布页面”中找到第 9 节发布的页面，点击“添加到菜单”。需要分组时，在“菜单结构”中“添加分组”，并拖动调整顺序。
3. 选中菜单项，在菜单属性中设置菜单名称、是否“在菜单中显示”、是否“设为应用默认入口”，以及访问权限（“跟随应用权限”或“为此菜单单独设置”）。
4. 在应用属性的“入口与导航”中设置启动页面、排列顺序和是否“置顶到应用栏”，最后点击“发布”。

菜单只能挂载已发布的组件页面，不再直接挂载表单。菜单的访问权限只控制入口是否可见，记录和字段权限仍由表单权限决定。

## 11. 授予表单权限

能看到应用和页面，不代表能读写表单数据。非管理员用户访问表单记录时，服务端按以下顺序判定，任何一层的显式“拒绝”都优先于“允许”：

1. 角色权限：在“后台设置 → 组织、身份与权限 → 角色管理”中点击角色的“权限”，在“配置角色权限”中“添加授权”，资源类型选择“表单”。资源编码填写表单编码或 ID（填 `*` 表示全部），授权结果为允许或拒绝。每条授权选择一个可执行动作（全部动作、查看、新建、编辑、删除、审批、导出、发布），需要多个动作时添加多条授权。数据范围可选全部数据、仅本人、本部门、本部门及下级等。“高级规则（条件、字段、优先级）”中还可以设置条件规则和字段规则。
2. 表单权限规则：从表单记录页的「编辑表单 → 权限管理」进入，或打开 `/form-settings/<表单 ID>?tab=permission`。按角色配置并保存权限草稿后，点击「发布更改」使规则生效。
3. 应用表单绑定：只有直接挂载表单的旧菜单会建立这种绑定。挂载组件页面的菜单不会建立绑定，因此新的应用必须通过前两种方式授权。

本例可以这样划分：发起人可查看、新增、编辑本人记录；处理人可查看和编辑本部门记录；主管可查看和审批，是否允许导出按业务要求决定。批量导入需要同时具有“导入”和“新增”权限；角色权限的动作下拉中没有单独的“导入”，需要导入时只能授予“全部动作”，或在完整设计器的“权限设计”中配置。配置完成后，可以在“组织、身份与权限”的“权限模拟”中选择用户，确认其实际权限。权限模型的完整说明见[权限模型](../../architecture/permissions.md)。

## 12. 发布后验收

使用实际业务账号，从应用菜单进入页面验收。管理员账号会绕过表单权限检查，设计器试填也不会走完整的服务端校验，二者都不能代替业务账号验收。

- [ ] 目标人员能看到应用、菜单和页面。
- [ ] 筛选方案、查询和重置按钮、列表列和默认排序符合配置。
- [ ] 新增时默认值、编码、选项和必填规则正确。
- [ ] 非法数值、格式错误或重复值在保存时被正确拦截。
- [ ] 保存后能重新打开记录，数据完整。
- [ ] 启用审批时，先“保存草稿”，再从记录详情“提交审批”，处理人能在“流程与待办”中收到待办。
- [ ] 审批通过、驳回等路径都能走通，驳回后申请人可以修改并重新提交。
- [ ] 没有权限的角色不能查看、编辑、删除、导入、导出或审批不该操作的记录。
- [ ] 启用了导入、导出或附件时，各完成一次真实操作。

验收会产生真实的业务记录和流程实例，建议使用可识别的验收数据，并按团队约定清理。

## 13. 后续变更与版本管理

修改已发布的表单时，重复“编辑 → 保存草稿 → 试填 → 发布配置 → 业务账号验收”的过程。已发布表单继续编辑期间，业务页面始终使用已发布的版本。

设计器工具栏的“版本管理”中：

- “工作草稿”显示当前草稿的状态（未保存、已保存、待发布、已同步），可以“保存草稿”或“检查并发布”。
- “用线上配置重置草稿”会放弃所有未发布的设计修改，用当前线上版本覆盖草稿。
- 发布记录列出每次发布的版本，可以搜索版本号，标注“线上生效”或“历史版本”。“查看详情”中有“表单字段”“版本变更”“发布时检查”三部分，都是只读快照。
- 任意历史版本都可以“恢复到草稿”：该版本的字段、布局、列表、权限和分析配置会写回草稿，该版本之后新增、快照里没有的字段会保留。恢复不会改变线上页面和业务数据，也不会回退物理表结构；需要检查草稿后再发布为一个新版本。流程设计不在恢复范围内。

## 14. 常见问题

**保存后业务页面没有变化。** 先确认改的是表单还是页面，以及是否已经发布。表单要在设计器中发布，页面要单独发布新版本。

**发布失败。** 根据发布提示处理对应字段或流程配置，再点击发布。

**选择控件没有候选项。** 检查来源类型、来源对象、取值字段、显示字段和筛选条件，以及来源数据是否对当前用户可见。静态选项要确认已经填写了选项。

**能看到菜单，却看不到记录或无法保存。** 菜单只提供入口。依次检查页面允许访问的角色、组件访问的权限组、角色的表单权限和字段规则，以及当前流程节点的要求。

**试填通过，实际保存仍失败。** 试填不写入数据，也不覆盖全部服务端校验。按页面返回的错误检查格式、数值、唯一性、字段权限、选项合法性和流程条件。

**提交后没有生成待办。** 确认业务人员执行的是“提交审批”，流程是通过设计器的“发布配置”发布的，“表单触发”中的动作已启用，处理人规则能解析到实际人员，且流程中没有并行网关。
