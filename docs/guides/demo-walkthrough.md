# 演示走查

更新日期：2026-11-17（对应代码版本 0.3.22 草稿）

本文面向需要向客户或同事演示 ManuFoundry 的人员，按当前界面的菜单区域（业务工作台、应用配置、数据中心、后台设置和 AI 助手）给出一条可以实际走通的演示路线，并说明每个区域当前的能力边界。系统整体结构见[系统概览](../architecture/overview.md)。

## 1. 准备演示环境

演示需要一个可登录的 PostgreSQL 环境。SQLite 模式下不会创建任何登录账号，不适合演示。

1. 按[后端开发指南](../development/backend.md)中“方式二：PostgreSQL”的步骤启动后端。首次对空库执行 `alembic upgrade head` 前，必须设置 `PALANTIR_SEED_ADMIN_PASSWORD`，迁移会用它创建 `admin` 账号。如果还需要演示角色账号，同时设置 `PALANTIR_SEED_DEMO_PASSWORD`。
2. 按[前端开发指南](../development/frontend.md)启动前端，打开登录页。
3. 用 `admin` 和 `PALANTIR_SEED_ADMIN_PASSWORD` 的值登录。

设置了 `PALANTIR_SEED_DEMO_PASSWORD` 后，迁移会创建以下演示账号，密码都是该变量的值：

| 账号 | 角色 |
| --- | --- |
| `pm_li` | 生产经理 |
| `qe_wang` | 质量工程师 |
| `mm_zhou` | 设备维护经理 |
| `me_sun` | 维修工程师 |
| `pe_huang` | 工艺工程师 |
| `scm_liu` | 供应链经理 |
| `wh_feng` | 仓储操作员 |
| `ds_he` | 数据专员 |
| `auditor_gu` | 审计观察员 |

**警告：`scripts/seed_data.py` 会把 `admin` 的密码重置为脚本中写死的弱密码，并把演示账号的密码改成统一的弱密码。** 它只能在本地演示库中运行，绝不能在任何对外可访问的环境中运行。

全新数据库中没有任何应用、业务表单或页面。仓库里的默认制造业应用（生产态势、预测性维护、质量分析、供应链风险）当前不会被自动创建，所以演示要从“应用配置”开始搭建一个应用（见第 4 节）。

## 2. 登录与界面框架

登录页标题为“登录你的工作空间”，填写“账号”和“密码”后登录。账号开启了多因素认证时，还需要输入 MFA 验证码。“企业 SSO 登录”在没有配置 OIDC 时会提示“企业 SSO 尚未配置”；登录遇到问题时，用户可以点击“无法登录？联系管理员”。

登录后的界面由三部分组成：

- 左侧应用栏：依次是“工作台”“流程与待办”“日常任务”、用户可访问的各个应用、“知识库”（仅管理员），以及“更多”。“更多”打开应用中心，可以在“搜索应用名称或用途”中查找应用并设为常用。
- 页头：全局搜索（“搜索应用、页面或表单”）、通知中心（可“全部已读”）和“版本记录”。
- 左下角用户菜单（“用户菜单与设置”）：进入设置中心或“退出登录”。设置中心按“个人设置”“应用配置”“数据中心”“平台管理”“高级工具”分组，非管理员只能看到自己有权访问的部分。

菜单区域的定义见 `frontend/src/config/navigation.ts`。

## 3. 业务工作台

业务工作台面向日常业务用户，包括三个入口：

- 我的工作台（`/`）：汇总“需要我处理”“我发起的”、最近工作和可填报的业务表单。新环境中这些模块都是空的；完成第 4 节后，这里会出现刚发布的表单。
- 流程与待办（`/workflow`）：按“待审批”“我发起的”“我已处理的”查看审批事项，可以在这里处理第 4 节中提交的申请。
- 日常任务（`/scheduler`）：登记定时任务。手动触发只会写入记录，系统没有按计划自动执行任务的调度器，演示时不要描述成自动运行。

## 4. 应用配置：搭建一个业务应用

“应用与菜单”“业务数据”“页面设计”三个入口仅管理员可见，“模板中心”所有用户可见。推荐的演示路线如下，各步骤的详细说明见[业务表单配置指南](low-code/business-form-guide.md)：

1. 在“业务数据”中点击“新增表单”，填写表单名称，在“字段结构”中用“新增字段”添加几个字段（例如文本、日期、单选、人员），然后“保存草稿”。
2. 点击“进入设计”，在“表单设计”中调整布局和必填项；如需审批，在“流程与审批”中配置审批节点。点击“发布配置”提交发布。
3. 在“页面设计”中“新建页面”，填写页面名称后“创建并设计”。在页面设置中添加“业务列表”组件，在组件的“数据”页签中选择刚发布的业务表单，并在“列表筛选”中“启用列表筛选”，配置筛选字段和查询、重置按钮。保存草稿后点击“创建首个版本”发布页面。
4. 在“应用与菜单”中“新增应用”，填写应用名称和编码，在“应用访问”中选择可访问的角色，先“保存草稿”（应用保存后才能添加页面）。然后在“已发布页面”中把刚发布的页面“添加到菜单”，最后点击“发布”。
5. 回到左侧应用栏打开新应用，演示新增、筛选、编辑记录；如果配置了审批，先保存草稿，再从记录详情“提交审批”，然后换一个演示账号在“流程与待办”中审批。

演示时需要注意两个边界。第一，“模板中心”中应用模板后界面会提示成功，但后端只返回模板的登记信息，不会导入任何表单、页面或数据。第二，运行时数据如何保存、权限如何生效，见[表单运行逻辑](low-code/form-interaction-logic.md)。

## 5. 数据中心

数据中心包括「数据资产」「基础数据」「对象与关系」和「知识库」。基础数据和知识库由管理员管理。

- 在「数据资产 → 连接管理」中添加连接，通过「资产目录」扫描并查看表和字段，在「同步任务」中查看任务。演示 PostgreSQL 环境以及各类连接和同步任务的运行方式见[数据接入与连接器](../architecture/integration.md)。
- 在「对象与关系 → 模型设计 → 字段映射」中选择「业务表单」或「外部数据源」。业务表单需要选定记录主键，可以右键匹配来源字段后保存绑定。外部数据源可右键选择「映射到现有属性」或「新建属性并映射」，在「候选审核」中确认后生效。
- 在「对象浏览」中沿关联记录跳转。「关系探索」展示当前账号有权访问的已发布对象记录及关系，可选定起点查看一层或两层。点击节点后，可在右侧查看属性与来源，并通过「编辑」修改有权限的属性名称和值。显示名称可以恢复为模型默认名称。修改对象主键时会同步更新关联引用，主键重复或关联更新受阻时整次保存回滚。
- 知识库：上传 SOP、CAPA、供应商报告等文档，进行识别、抽取、审核和检索。仓库的 `data/knowledge_assets/` 中有可直接使用的演示文件，完整操作见[知识库使用流程](knowledge/knowledge-workflow.md)。

## 6. 后台设置

后台设置仅管理员可见，分为“数据与集成”“分析与追溯”“开发与配置”“平台管理”四组。演示中常用的是：

- 组织、身份与权限：管理用户、组织和角色。在“角色管理”中点击“权限”可以为角色配置表单等资源的授权，并用“权限模拟”验证某个用户能看到什么。权限规则见[权限模型](../architecture/permissions.md)。
- AI 与平台设置：配置 AI 模型服务。没有配置有效的模型服务时，AI 助手无法回答问题。
- 审计与日志：查看平台审计日志。
- 质量影响与时间线：展示质量异常与 SOP、历史 CAPA 等知识证据的关联。它依赖制造业演示数据和已发布的知识资产，新环境中通常没有可展示的内容。

## 7. AI 助手

页面右下角的“打开 AI 助手”按钮打开浮窗，可以新建会话、查看历史记录。AI 助手需要先在“AI 与平台设置”中配置模型服务。在表单设计器中，管理员还可以让 AI 生成表单草稿，生成结果需要点击“确认创建草稿”后才会保存。

## 8. 当前能力边界

演示时请避免把以下内容描述为现有功能：

- MES、ERP、IoT、PLC 等外部系统的真实连接器，以及 MySQL、SQL Server、Oracle 的真实连接（都未实现）。
- 数据同步和同步管线的实际数据搬运（当前为模拟运行）。
- 按计划自动执行的日常任务（没有调度器）。
- 模板中心一键导入应用（只登记，不导入）。
- 并行网关审批（设计器中可以画出，但发布时会被拒绝；会签和或签请使用同一节点的多个审批组）。
