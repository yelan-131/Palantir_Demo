# 业务表单使用指南：从配置到发布

更新日期：2026-10-26  
适用对象：业务管理员、实施人员、表单配置人员、验收人员。  
文档依据：当前仓库实现。实际菜单名称、可用入口和角色权限以部署环境为准。

如果目标是不使用现有源码、从空工程自行编写一个表单系统，请阅读
[从零编写业务表单系统：开发规格与实现指南](../development/business-form-from-scratch.md)。本文面向已建好系统中的配置操作。

本文以“设备告警处理单”为例，说明如何建立业务表单、配置填写与查询规则、设置流程和权限，并发布给业务人员使用。文中的字段、角色和流程为配置示例，需要按实际业务建立。

## 1. 先了解完整流程

一张业务表单需要同时具备数据结构、填写界面、列表查询、业务流程和访问权限。建议按以下顺序配置：

1. 明确用途、使用人员和业务字段。
2. 新建业务表单，保存基本信息。
3. 配置字段、控件、默认值和校验规则。
4. 配置填写布局、列表与筛选。
5. 配置流程与审批、角色及字段权限。
6. 保存配置草稿，试填并检查。
7. 检查影响报告，确认发布表单。
8. 配置应用菜单；使用组件页面时，另行发布页面布局。
9. 使用实际业务账号完成运行页验收。

**配置草稿、已发布配置、业务记录是三类不同内容。**“保存草稿”在设计器中保存的是配置，在业务填写页中保存的是一条未提交的业务单据。“发布配置”使表单规则生效，“提交表单”则是业务人员提交一条具体单据。

## 2. 配置前准备

开始前，确认自己具备管理与配置权限。当前表单发布接口要求管理员身份；能够查看表单，并不代表能够发布表单。

先准备以下信息：

- 表单名称、编码、用途说明，以及所属应用和菜单位置。
- 业务字段及其类型、是否必填、默认值、选项来源。
- 使用角色，例如告警发起人、处理人、主管。
- 是否需要审批，什么动作触发流程，各节点由谁处理。
- 需要引用的数据字典、基础档案、人员组织或其他业务表单。

例如，“设备告警处理单”用于登记设备异常、分配处理人、补充处理结论并由主管审核。先确定这些业务要求，再开始拖拽控件，能减少后续返工。

## 3. 新建业务表单

在应用装配的表单资源区域新建表单，选择类型“业务表单”，填写基本信息并保存；已有表单可以直接进入设计。不同界面可能通过独立设计页或页面内嵌编辑器打开配置。

本例建议填写：

- 表单名称：设备告警处理单。
- 表单编码：`equipment-alert`。
- 说明：登记设备告警、处理记录和审核结论。
- 数据实体：根据项目实际业务对象填写。

表单编码用于标识和路由匹配，保存后在基本信息界面中不可直接修改。名称用于展示，编码用于识别，两者应分别确定。

数据来源在该创建界面中由系统生成。底层支持 JSON 动态记录和表单托管物理表两种存储方式；创建物理表单或新增物理字段可能立即建立表、列，不能把所有结构配置都理解为发布前完全不影响数据库。

**本步完成标志：**表单已保存，可以进入设计器维护字段和布局。

## 4. 配置字段和填写规则

### 4.1 建立字段结构

每个字段至少要明确显示名称、字段标识和数据类型，再配置录入控件及使用规则。字段标识应稳定、含义清楚；已有数据后，修改类型或收紧约束需要先检查历史数据。

本例可以配置：

- **告警编号**：编码字段，按规则自动生成。
- **告警标题**：文本，必填，参与列表展示和搜索。
- **设备**：关联对象，来源为设备基础档案。
- **告警等级**：枚举，候选项为普通、重要、严重。
- **责任人**：人员选择，来源为用户组织。
- **发生时间**：日期时间。
- **处理结论**：多行文本。
- **附件证据**：附件上传。

类型要与实际值匹配：数量或金额使用数值，时间使用日期或日期时间，有限的状态集合使用枚举。不要仅靠字段名称表达类型。

### 4.2 配置控件和选项来源

进入“表单设计”；在页面内嵌模式下，该页签显示为“填写表单”。将字段加入画布，选中后在属性区设置控件、提示文字、宽度及规则。

选择类控件支持的来源包括静态选项、数据字典、基础档案、业务表单、用户组织和外部接口。按来源补齐对象、取值字段、显示字段及筛选条件。

例如，设备字段可以保存设备 ID，显示设备名称。静态枚举可使用稳定编码作为选项值，中文名称作为显示标签。后续调整显示名称时，应保留历史记录使用的选项值。

配置后检查：

- 单选、多选与展示方式是否匹配。
- 选项值是否重复、来源能否返回候选项。
- 默认选项是否包含在候选集合内。
- 多选数量限制与默认选中数量是否冲突。
- 使用搜索选择时，查询字段和过滤范围是否正确。

### 4.3 配置默认值、编码和计算

为需要预填的字段设置固定默认值或默认值规则。存在字段引用时，检查引用字段是否有效、依赖关系是否成环，并通过试填验证结果。

编码字段可配置固定文本、日期时间、字段值、基础档案、组织信息和流水号等组成段，同时选择生成时机、重置规则和唯一范围。例如可设计成 `AL-日期-流水号`。试填中的编码效果不能代替正式保存时的唯一性验证。

配置计算表达式时，确认引用字段、结果类型以及空值、零值、小数等情况。发布后还要在业务页保存一条记录，验证服务端实际处理结果。

### 4.4 配置校验和字段状态

根据业务需要设置必填、只读、隐藏、格式、长度、数值范围或唯一性等规则。不要同时将一个无可靠赋值来源的字段设为隐藏且必填。

例如，“处理结论”可以在处理节点要求填写；“告警编号”由系统生成，业务人员只读。节点要求需要与流程和字段权限一起检查。

**本步完成标志：**输入控件都绑定有效字段，选择控件有可用来源，默认值有效，必填字段可填写或有可靠的自动赋值方式。

## 5. 配置填写布局、列表与筛选

### 5.1 填写布局

按业务步骤对字段分组，例如“告警信息”“处理信息”“审核信息”。调整排列顺序、控件宽度和说明文字，让使用者能顺着业务流程填写。

同一字段应只绑定一个输入控件。复制控件后，要检查是否产生重复绑定；纯布局容器不需要绑定业务字段。

### 5.2 列表与筛选

进入“数据筛选”；在内嵌模式下，该页签显示为“列表与筛选”。配置查询条件、表格列、排序及工具栏动作。

本例建议：

- 列表展示告警编号、标题、设备、等级、责任人和发生时间。
- 筛选条件包括告警等级、设备、责任人和发生时间范围。
- 默认按发生时间倒序。
- 将标题等字段设为可搜索，便于快速定位记录。

字段加入填写表单、加入列表和参与搜索是不同设置，需要分别确认。复杂说明和附件可以保留在填写或详情中，避免列表过宽。

如果配置多个数据视图 Tab，需要为每个 Tab 设置展示列及角色、用户或组织可见范围。Tab 可见范围用于组织视图，实际记录和字段访问仍受后端权限约束。

新增、导入、导出等入口既要在界面配置中启用，也要给对应角色授予权限。例如，批量导入还要求同时具有“导入”和“新增”权限。

**本步完成标志：**常用记录能通过筛选找到，各视图有有效列，工具栏动作与角色职责一致。

## 6. 配置流程与审批

进入“流程与审批”，确认流程名称、节点、连线、处理人和触发绑定。

本例可采用“开始 → 处理人处理 → 主管审核 → 结束”的流程，按实际场景设置分支及驳回路径。配置时依次检查：

1. 开始和结束节点完整，执行节点已经连入流程。
2. 每个审批节点都配置处理人来源，并能解析到实际人员。
3. 根据业务选择单人、或签或会签方式。
4. 条件分支能覆盖实际字段值，避免记录进入无后续路径的状态。
5. 在触发绑定中确认哪些业务动作启动流程，例如“提交表单”。
6. 核对节点字段权限及状态映射。

流程画布中的节点并非全部支持运行。定时事件、脚本任务、子流程等存在仅用于设计展示的类型，使用前应确认当前执行支持；以设计器检查结果和实际流程验收为准。

保存配置草稿会保存流程设计草稿。正式发布还涉及流程定义和动作绑定；仅把节点连起来，不能证明业务提交后一定会生成待办。

如果已有流程加载失败，设计器会阻止保存和发布，避免覆盖原有流程。应先恢复加载，再继续配置。

**本步完成标志：**流程检查通过，处理人有效，触发动作明确；发布后还需验证一条实际单据的流转。

## 7. 配置角色、动作和字段权限

进入“权限设计”；在内嵌模式下，该页签显示为“权限管理”。按角色分别配置页面访问、业务动作和字段能力。

本例可以采用以下职责划分：

- 发起人：查看、新增、保存业务草稿、提交。
- 处理人：查看并处理业务允许范围内的记录，填写处理结论。
- 主管：查看、审批；是否导出由业务要求决定。

以上是配置目标；“只看本人记录”等数据范围要求，需要单独核实部署环境的实际能力，不能仅通过角色名称推断。

继续检查字段是否可见、可编辑、可导出，以及特定节点是否必填。例如处理人在处理节点填写结论，主管在审核节点查看结论和附件。

应用入口、页面访问、表单动作和字段权限需要同时满足。给角色显示一个菜单，不等于给它授予表单数据权限；隐藏页面按钮也不能代替服务端权限检查。

**本步完成标志：**每个角色都具备完成职责所需的动作和字段权限，没有把只读用户配置成可编辑或可审批。

## 8. 保存草稿、试填和本地检查

点击“保存草稿”，确认保存成功后再离开。保存失败时，当前修改可能仍保留在编辑器中，应修复问题后重新保存。

已发布表单继续编辑时，运行页的表单定义以已发布快照为准。这个机制不代表所有底层结构操作都延后执行：物理表和字段的创建可能已发生，见第 3 节。

打开“表单预览”或“试填表单”，选择预览角色及流程节点，检查：

- 字段顺序、宽度、提示和分组是否清楚。
- 必填、只读、隐藏是否符合当前角色和节点。
- 默认值、选择数量和选项来源是否正确。
- 当前角色是否能填写所需字段。

试填内容不会保存为业务记录。“检查必填项”主要验证预览中的必填与选择数量；数值、格式、字节限制以及实际权限等，还需在运行页验证。

查看“本地配置检查”，处理缺少必填字段、输入控件未绑定、字段重复绑定、默认值引用错误、视图列为空、无效字段引用和流程不完整等问题。检查随草稿配置更新，发布时另有服务端检查。

## 9. 检查并发布表单

### 9.1 进入发布检查

点击“发布配置”，在内嵌模式下为“发布更改”；也可以从“版本管理”进入“检查并发布”。

系统会先保存当前配置草稿，再请求服务端发布预检查，之后打开“发布确认”。进入确认窗口不等于已经发布。

### 9.2 阅读检查结果

发布检查会结合配置和现有业务记录给出阻断、提醒及信息。

常见阻断及处理方式：

- **新增必填字段，但历史记录没有值**：先以可选字段发布并补齐历史数据，再改为必填。
- **可选字段改为必填，但历史数据存在空值**：先补齐空值，再重新检查。
- **字段类型与历史值不兼容**：先确认业务和数据转换方案，完成数据处理后再发布。
- **删除了历史记录仍使用的枚举值**：先保留旧值，或完成历史值迁移。
- **控件或规则配置无效**：返回对应配置页修复，再发起检查。

归档或移除带历史值的字段可能产生提醒：历史数据保留，但不再出现在新的填写表单中。应确认业务仍能按需要查询历史信息。

不要只看“有没有报错”，还要阅读影响记录数、字段名称及提醒内容。默认值配置也不能代替对历史数据的实际补齐。

### 9.3 确认发布并核对版本

阻断项处理完成、影响确认后，点击“确认发布”。正式发布时服务端还会重新检查，预检查通过不代表最终提交一定成功。

发布成功后会生成一份新的表单版本快照，并同步已发布权限。运行页读取新的已发布定义。打开“版本管理”，确认出现新版本和发布时间，再刷新业务页检查效果。

如果发布失败，不要仅凭流程定义已更新或页面局部发生变化就判断成功。当前发布包含多次请求，应以表单发布成功、版本记录和运行页验证共同确认；失败后检查流程定义、绑定及表单版本状态，再重试。

## 10. 配置应用入口与页面发布

在应用装配中，将业务表单绑定到目标应用菜单，设置菜单名称、位置和默认入口，并确认目标人员有应用访问权限。

业务入口通常为 `/dynamic/:slug`，也可能由 `/program/:programId` 进入。入口会根据绑定情况加载组件页面或原有业务页。

**组件页面的发布与来源业务表单的发布独立。**

- 修改字段、填写规则、列表规则、流程或数据权限：进入来源表单编辑器，发布表单更改。
- 修改组件布局、组件显示、页面样式或页面访问角色：保存页面草稿，再点击“创建首个版本”或“发布新版本”，完成页面发布确认。

组件页面可通过画布右键菜单中的“字段与录入”“列表与筛选”“流程与审批”“数据权限”进入来源表单编辑器。

如果两类配置都修改过，应分别发布。页面发布不会自动发布来源表单草稿，表单发布也不能代替组件页面发布。页面提示“请先发布来源业务表单”时，先完成来源表单发布。

## 11. 发布后验收

使用实际业务账号，从应用菜单进入运行页验收；仅使用管理员账号或设计器试填，无法完整验证普通用户权限。

- [ ] 目标人员能看到应用、菜单及页面。
- [ ] 列表列、筛选条件、默认排序符合配置。
- [ ] 新增时默认值、编码、选项和必填规则正确。
- [ ] 非法数值、格式错误或重复值在实际保存时得到正确处理。
- [ ] 保存后能重新打开记录，数据没有丢失或显示异常。
- [ ] 启用审批时，提交生成正确流程实例和待办，处理人能够接收。
- [ ] 审批通过、驳回等实际配置的路径能够完成，字段权限符合节点要求。
- [ ] 无权限角色不能查看、编辑、删除、导入、导出或审批不应操作的内容。
- [ ] 若启用导入、导出或附件，分别完成一次真实操作。
- [ ] 历史记录仍能按预期读取和处理。

正式环境验证会产生业务记录和流程实例，建议使用可识别的验收数据，按团队约定处理。

## 12. 后续变更与版本管理

修改已发布表单时，重复“编辑 → 保存草稿 → 试填 → 检查并发布 → 运行页验收”的流程。

“版本管理”可以查看发布记录、字段快照、与上次发布的变更，以及发布时保存的检查结果。历史快照是只读的，检查结果反映当次发布时的情况。

需要放弃当前设计修改时，可以选择“用线上配置重置草稿”。该操作会用当前线上版本覆盖布局、数据视图、权限及流程关联配置，并恢复字段默认值；未保存和已保存但未发布的设计修改都会被替换。

**重置草稿不回滚线上版本、不删除业务记录，也不完整恢复字段结构。**当前实现没有在该入口提供任选历史版本后一键回滚全部配置、数据和物理表结构的能力。需要恢复旧行为时，应核对历史快照、调整草稿，再发布为新版本。

## 13. 常见问题

### 保存后为什么业务页没有变化？

先确认保存的是配置草稿还是已发布配置。检查表单发布记录；如果改的是组件页面布局，还要检查页面是否独立发布。

### 发布按钮不可用或一直被阻断怎么办？

先检查权限、流程加载状态、本地配置错误和服务端影响报告。处理阻断项后重新发起检查，确认网络及登录状态正常。

### 选择控件没有候选项怎么办？

检查来源对象、取值字段、显示字段、筛选条件及来源数据权限。使用静态选项时，检查是否实际配置了选项及有效默认值。

### 看得见菜单，却看不到记录或无法保存怎么办？

依次检查应用访问、页面角色、表单查看与写入权限、字段权限，以及当前流程节点要求。菜单展示只负责提供入口。

### 试填通过，实际提交仍失败怎么办？

试填不写入业务记录，也不覆盖全部服务端检查。根据运行页返回的错误检查格式、数值、唯一性、字段权限、选项合法性及流程条件。

### 发布成功，业务提交后却没有待办怎么办？

检查实际执行的是否为“提交”动作、触发绑定是否启用、流程定义是否已发布，以及处理人规则是否能找到有效人员。
