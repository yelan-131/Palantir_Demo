# 全站 UI 优化与验收记录

日期：2026-11-10。使用项目级 Impeccable 4.8.2，沿用 0.3.21 草稿，未提交、推送或部署。

## 实际改动

- 保留灰蓝主题，主题源仍为 `frontend/src/theme/techWhite.ts`。提高辅助文字和图标对比度，统一占位文字、默认控件高度与菜单圆角；补充公共间距变量。
- 新增 `frontend/src/ui-system.css`，集中管理导航选中态、标题层级、搜索焦点、键盘焦点、数字排列、滚动区、设置页和工作台的公共视觉细节。
- 应用布局增加键盘“跳转到页面内容”入口，路由加载改为骨架及状态说明，减少动态效果设置下关闭骨架动画。
- 工作台移除重复的装饰性上标题，统一辅助文字、图标和业务状态颜色。已发布画布的容器外观、尺寸、密度、配色与数据编码仍由既有配置决定。
- 登录页移除重复边框和装饰编号，修正介绍标题的 h1→h3 跳级，修正输入占位文字对比度。600px 以下优先显示登录表单，桌面保留产品介绍与原有交互。
- 应用与菜单、业务来源读取失败显示错误和重试，不再把失败表现为空应用。数据源列表同样保留错误与重试，并提供具体的无数据提示。
- 用户搜索与刷新按钮补充可访问名称；保留权限、接口、字段配置、排序、分页、审批和发布语义。

## 验证环境与结果

浏览器连接真实本地 React/Vite 前端和 FastAPI 后端。后端使用独立临时 SQLite 数据库 `/tmp/manufoundry-ui-polish/review.db`，载入仓库演示数据、测试身份，并通过现有 API 创建验收应用、一张已发布的五字段表单与六条验收记录。未连接生产服务器或修改现有业务数据库。

- 最终 `npm run build` 通过；仍有部分打包产物超过 500 kB 的体积提示，本轮未调整拆包策略。
- 最终 `node --test tests/*.test.cjs`：204 项通过，0 失败。
- Impeccable 初次联合检查覆盖本轮源码和实际渲染登录页，发现登录占位文字低对比度、重复容器与标题跳级。修复后对受影响源码及渲染登录页复查，结果为 `[]`，退出码 0。该结果不代表所有已登录页面完成自动可访问性审计。
- 查看 18 个主要路由及登录页：工作台、应用管理、业务数据、页面设计、数据接入、数据资产、对象与关系、用户管理、账号、工作偏好、流程与待办、AI 设置、应用中心、业务记录、表单设计器、模板、日常任务和插件。记录页及设计器使用临时数据库的验收表单；设计器通过业务数据入口 `/form-settings/1?source=business-data` 验收。
- 桌面 1440×1000；主要页面另检查 390×844。用户目录补充 900×900 与 1024×900 检查，页面文档宽度未超出对应视口，宽表格和设计器按现有规则在内部滚动。
- 交互检查通过：键盘跳转、菜单折叠/展开、用户搜索/清空/详情、数据源错误重试、应用错误重试到成功空状态、手机弹窗尺寸、登录必填校验及实际登录、真实记录详情与手机录入表单。
- 使用非管理员演示账号验证受限入口仍显示“需要管理员权限”。

## 验证边界

- 数据资产与对象关系接口在本地缺少图数据库时返回 503；AI 注册表尚未初始化时返回 409。这些页面未出现前端运行异常，但其完整数据流程需要相应服务，不作为本轮已通过的业务验收。
- 历史直接访问 `/form-settings/1` 的加载状态未列为通过；经业务数据入口带 `source=business-data` 的设计器已实际查看。本轮未改动设计器路由语义。
- 大量数据、复杂流程、全部角色组合、所有自定义主题和真实外部数据源尚未穷尽测试。未修改生产配置或自动发布任何页面。
- 临时验收脚本和凭证只在 `/tmp/manufoundry-ui-polish`，不纳入仓库；截图中的身份、工单和应用均为演示验收数据。
