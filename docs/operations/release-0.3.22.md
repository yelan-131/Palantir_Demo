# 0.3.22 — 业务列表内置筛选与接口鉴权加固

- 状态为待发布，更新于 2026-11-17（北京时间）。
- 上一发布版本为 [0.3.21 — AI 技能、应用页面与数据中心](release-0.3.21.md)。

在页面设计器中选中业务列表，打开「数据 → 列表筛选」，即可启用表格上方的筛选区，配置筛选方案、关键词搜索、筛选字段和查询按钮。筛选使用列表已绑定的业务来源。列表会显示当前筛选方案的页签，包括只有一个方案的情况。筛选字段配置包含「字段」「使用」「选择方式」三列，启用的选项字段可设置单选或多选控件。切换组件属性页签后回到「数据」，会恢复该列表上次编辑的筛选方案和面板滚动位置。新增筛选方案时会停留在当前页签，并把当前方案的权限组、适用对象、筛选字段和选择方式复制到新页签。两个方案可各自修改。「适用对象」「筛选区域」和「查询与重置按钮」依次并列在筛选方案下，使用与列表显示一致的二级属性样式。方案页签直接排在「启用列表筛选」下方，右侧集中放置新增和删除当前方案的按钮。选中页签与配置区使用统一底色。适用对象为空时提供一行空白输入。筛选区域包含关键词搜索与筛选字段，按钮区用于配置查询与重置行为。筛选区域移除新增与复制权限组的入口，查询与重置按钮区域移除新增、复制与删除权限组的入口。查询和重置按钮沿用当前筛选方案的适用对象。旧按钮权限组里曾启用的按钮汇总为列表的按钮设置。

组件库与 AI 页面配置已移除独立筛选的新增功能。旧版独立筛选可以从画布移除。

编辑旧页面时，同来源、无独立访问限制且只关联一个列表的单个筛选组件会合并进列表草稿。浏览页面时按相同规则显示合并后的布局。已配置的列表筛选优先保留，历史快照保留原始定义。共享或具有独立访问限制的旧筛选保留运行兼容。

页面编辑器在并排布局时自动填充属性栏旁的可用宽度和高度。内容超出时在画布区域内纵向滚动。右侧属性面板内的筛选字段和显示列随属性内容连续滚动，标题、页签和发布栏固定。属性内容获得焦点后可用键盘滚动。

单列表页面在浏览和编辑时都填满可用高度，分页位于列表底部。右键菜单不改变画布尺寸，打开桌面属性栏只收窄画布；窄屏筛选可换行，小窗口仍可滚动画布访问分页。

每个筛选方案可以在「筛选区域」设置默认行数和每行筛选项数量。默认预留两行，每行四个筛选项，关键词占一格。窄屏每行最多两个。字段较多时继续换行，查询和重置按钮排在筛选区域下方。

权限组页签直接排在「列表显示」下方。选中后可编辑该组的名称、适用对象和列表显示设置，右侧提供新增、复制和删除。切回「数据」时恢复上次选中的权限组。

筛选配置保存在页面定义中，无数据库结构迁移。可通过页面历史恢复先前布局。

## 接口鉴权与生产暴露面

升级后，以下接口的访问要求有变化，调用方需要携带有效登录凭据：

- 模型驱动元数据（模型、字段、页面、菜单、规则）仍允许登录用户读取，写入改为仅平台管理员（租户 1 的管理员）可用。这些表为平台级共享，租户管理员不再能修改。
- 配置导入导出整体改为仅平台管理员可用。数据库导入的替换模式会跨租户删除，因此不再开放给租户管理员。
- 全局搜索、模板、设备维护、AI 构建和知识库接口改为必须登录；此前这些接口可匿名访问。
- `/api/v1/system/metrics` 改为管理员登录后访问。
- 公开接口仅保留首页、`/health`、系统就绪检查、当前版本、产品化就绪检查、登录、邀请接受、OIDC、密码重置，以及使用独立令牌校验的 Harness MCP 桥接。新增回归测试会拦截任何未登记的匿名接口。

生产部署（`docker-compose.prod.yml` 与 `docker-compose.release.yml`）中，后端、PostgreSQL 和 Neo4j 端口仅绑定 `127.0.0.1`，公网只经前端 nginx 的 80 端口访问 `/api/` 与 `/health`。生产环境关闭 `/docs`、`/redoc` 与 `/openapi.json`。部署后通过 `http://<服务器>/health` 检查后端健康状态，不再直连 8000 端口。

JWT 签发与校验、密码哈希不再在依赖缺失时降级为 base64 令牌或 SHA-256 哈希。已有 `sha256$` 前缀的种子账号密码仍可校验登录，新密码统一使用 bcrypt。

全局搜索改为在每次请求时读取可搜索的文本列，运行时注册的模型也能被搜索到。

## 手动发起流程的业务记录关联

`POST /api/v1/workflow/definitions/{id}/start` 关联业务记录时（`resource_type` 为 `dynamic_record`，或 `variables` 中带 `form_id`、`record_id`），须在 `variables.form_id` 指定来源表单，并提供记录 ID。平台会校验表单属于当前租户、记录存在且发起人有查看权限。`variables.record_id` 与 `resource_id` 不一致时拒绝。只传标题和表单数据的普通发起不受影响。

此前只按记录 ID 关联的旧实例，只有在记录所属表单与该流程存在绑定时，才会在流程中心挂到这条记录下。否则按无关联实例处理，仅发起人、审批人和管理员可见。不同表单的记录 ID 可能相同，此前这类实例可能显示在无关记录及其创建人的收件箱中。

无数据库结构迁移。

## 移除 Redis 与未使用代码

后端代码从未连接 Redis，本次从三份 Docker Compose 文件、私有部署脚本、部署诊断脚本、环境变量示例和后端依赖中移除 Redis 服务。从旧版本升级的服务器上仍会残留 `manufoundry-redis` 容器，可在更新时使用 `docker compose ... up -d --remove-orphans` 移除，再按需删除 `redis_data` 数据卷。

同时删除未被引用的后端模块：空的 `app/schemas` 包、`services/analytics`（预测性维护、供应优化）、`services/data_integration`（MES 模拟器、管道引擎）、旧版演示种子与语义记录预览、旧版提示词与运行时配置模块。Harness 之前的智能体规划器代码只用于测试中生成历史提案数据，已迁到 `backend/tests/legacy_agent/`，运行时始终使用 Harness。

## SQLite 模式下 AI 修改应用误报配置已变化

使用 SQLite 数据库时，通过 AI 修改、发布、停用或重新启用应用，确认卡片后可能提示「应用或菜单配置已变化，请重新确认」。原因是确认时为加写锁执行的占位更新会刷新应用的更新时间，确认快照因此与预览不一致，只要预览和确认不在同一秒就会发生。现在加锁不再改动更新时间。PostgreSQL 部署不受影响。

## 后端分层

表单引擎（存储、命名、编码、查询、校验、序列号）从 `app/api/form_engine` 移到 `app/services/form_engine`。服务层改从 `app/core/principal` 获取租户、用户和管理员校验，不再依赖路由层的 `app/api/deps`。通用权限与表单权限的 FastAPI 依赖工厂 `require_permission`、`require_form_permission` 移到 `app/api/deps`。新增分层测试，禁止 `app/core`、`app/models`、`app/services` 引用路由模块。接口行为不变。


## 巨型模块拆分

后端告警记录、看板程序查询、应用 CRUD、流程视图与审批辅助、知识检索、组件页面定义与编辑器、表单发布载荷、表单管理 CRUD、应用菜单节点、表单流程启动等逻辑从路由模块迁入 `app/services`。路由层保留 HTTP 入口，并按需再导出服务符号供旧调用方兼容。此前未实现的知识绑定候选接口 `/knowledge/binding-candidates` 及前端 `suggestKnowledgeBindings` 已删除。

前端 `FormSettings/index.tsx` 的模块级类型、权限草稿、选项、字段与编码、设计器配置、平台字段、流程配置、分析设计器面板、发布校验等拆到同目录子文件；页面组件仍集中编排交互。类型检查与生产构建已通过。

## 持续集成

新增 GitHub Actions 工作流 `.github/workflows/ci.yml`，在推送到 `main`/`master` 和提交 Pull Request 时运行：

- 后端全部测试（Python 3.11，SQLite），按测试文件分四片并行。
- 在空的 PostgreSQL 16 数据库上执行 `alembic upgrade head`，并运行仅在 PostgreSQL 上生效的行锁与并发测试。
- 前端 `npm ci` 与 `npm run build`。

CI 不构建镜像，也不部署。

## 后端测试更新

部分后端测试仍按旧行为编写，与当前实现不符，本次更新这些测试，业务代码不变：

- 直接调用路由函数的测试补充当前用户；依赖已移除制造业演示目录的测试改用测试夹具注入。
- 模板测试改为当前的清单包结构。
- AI 测试改为先加载工具定义（`platform.tools.describe`），再调用工具（`platform.tools.invoke`）。这是 0.3.21 引入的工具按需加载方式。表单搭建技能版本改为引用技能版本表。
- 绑定提交审批的表单新建记录先保存为草稿，测试改为显式提交后再校验启动的审批流程。
