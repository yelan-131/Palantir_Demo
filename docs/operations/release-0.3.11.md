# ManuFoundry 0.3.11 版本说明

发布日期：2026-10-15

## 新增与优化

- 统一业务记录服务，表单、告警、料号申请、AI、看板和工作流共享租户及记录权限检查。
- 接入 `deepseek-harness-sdk==0.1.5rc1` 与配套 Node/Cordis 运行时，通过请求级 MCP 能力令牌调用现有平台工具。
- 应用公开请求使用 Harness 内核；旧 Agent 状态机单独保留为历史兼容实现。
- 完善持久化 AI 配置、模型连接测试、RAG、OCR、上下文与工具注册表设置。
- 工具调用重新校验当前权限和输入；写入通过平台确认，保留审批、审计及重复执行保护。
- 调整账号中心 AI 设置、登录界面和共享样式。
- 增加真实 SDK 集成、AI 配置与统一记录服务测试；提供隔离 PostgreSQL 验证脚本。

## 发布与部署

- 使用现有 `scripts/bump_release.py` 更新前后端版本号、两份发布清单及更新弹窗历史记录。
- 构建前运行 `python scripts/sync_ai_assets.py` 同步 Agent 指令、技能与工具打包资源。
- 后端依赖升级到 Pydantic 2.14.1，并安装固定版本 Harness SDK 和匹配运行时；不能只替换前端静态文件。
- 模型 API 凭据继续使用服务器现有配置，SDK 安装本身不提供模型服务。未配置可用模型时界面明确提示，不自动回退到旧内核。
- 数据库结构不新增迁移，不覆盖现有业务数据、知识资料、自定义工具定义或账号配置。
- 注册表升级脚本仅用于将原有占位草稿工具改为已实现处理器；不自动覆盖自定义定义。升级前先检查现有配置。
- 保持单 worker 部署；当前 MCP 能力令牌保存在进程内，多 worker 需要共享桥接服务。
- 技术细节见 [DeepSeek Harness runtime](../architecture/deepseek-harness-runtime.md)。

## 发布验证

- 前端生产构建与 TypeScript 检查。
- Harness 真实内核集成、AI 配置、业务记录、版本元数据及后端回归测试。
- Linux 服务器运行时依赖与模拟模型/工具闭环检查。
- 公网版本接口返回 0.3.11，保留历史记录并启用更新弹窗；前后端健康正常。

## 验证记录与已知限制

- 前端构建通过；163 项 AI、真实 Harness、记录服务和版本重点测试通过。
- 整体回归：594 项通过、52 项失败；同环境下对发布前提交 `17f52b5` 的独立副本回归为 562 项通过、54 项失败。失败用例集合对比未出现新增失败。
- 现有失败集中于旧配置导入、看板、规则/调度直接调用、模板种子及共享数据隔离用例；本次发布不宣称整体测试全部通过。完整日志保存在发布操作主机的临时目录，服务器发布备份中另存验证汇总。
- 服务健康不代表已完成真实外部模型验收；本次使用本地模拟模型验证内核和工具闭环，不调用生产模型或改写模型密钥。
