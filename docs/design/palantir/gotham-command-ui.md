# Gotham 风格智能运营指挥台 UI 设计

状态：设计（产品构想，参考 Palantir Gotham）

本文描述目标中的指挥台界面，不是对当前代码的说明；最接近的现有页面见第 6 节对照。总览见[关系图](relationship-map.md)。

> 日期：2026-05-20；与现有模块的对照更新于 2026-11-17（代码版本 0.3.22 草稿）。
> 范围：说明如何借鉴 Palantir Gotham 式“事件驱动、态势画布、行动方案、时间轴”的 UI 结构，设计制造业智能运营指挥台。
> 目标：让 ManuFoundry 的前台不只是后台表格，而是能展示风险、关系、方案和闭环的指挥调度界面。

## 1. Gotham 风格在这里代表什么

这里的 Gotham 风格不是军事题材，也不是照搬地图界面，而是借鉴它的交互结构：

```text
左侧：事件 / 情报 / 方案列表
中间：地图或态势画布
右侧：方案详情 / 资源 / 审批 / 风险提示
底部：时间轴 / 计划 / 执行步骤
```

制造业版本应替换为：

```text
左侧：质量异常 / 供应链风险 / 设备预警 / 待处理任务
中间：业务图谱 / 生产拓扑 / 供应链影响路径
右侧：AI 建议 / 处置方案 / 业务动作 / 审批按钮
底部：处理时间线 / 工单进度 / 流程状态
```

传统后台页面通常是“左侧菜单、中间表格、新增/编辑表单”。指挥台应改为“左侧事件队列、中央态势画布、右侧行动面板、底部时间轴”，从菜单驱动转向事件驱动。

## 2. 页面结构

```text
┌──────────────────────────────────────────────┐
│ 顶部：全局搜索 / 通知 / 当前角色 / 应用切换   │
├──────────────┬──────────────────┬────────────┤
│ 左侧事件栏    │ 中央态势画布       │ 右侧行动栏 │
│              │                  │            │
│ 高风险事件    │ 影响关系图         │ AI 分析    │
│ 处理中事件    │ 生产线拓扑         │ 处置方案   │
│ 我的任务      │ 供应链路径         │ 审批动作   │
│ 过滤器        │ 订单影响范围       │ 所需资源   │
├──────────────┴──────────────────┴────────────┤
│ 底部时间轴：发现异常 -> 分析 -> 派单 -> 审批 -> 闭环 │
└──────────────────────────────────────────────┘
```

各区域职责概览：

| UI 区域 | 职责 | 制造业示例 |
| --- | --- | --- |
| 顶部栏 | 全局搜索、通知、用户、应用切换 | 搜索物料、工单、供应商、客户订单 |
| 左侧事件栏 | 当前角色需要关注的事件和任务 | 质量异常、低库存、设备预警、待审批 |
| 中央态势画布 | 展示对象关系、影响路径、业务拓扑 | 供应商 -> 物料 -> 工单 -> 设备 -> 质检 -> 客户订单 |
| 右侧行动栏 | AI 总结、建议动作、审批按钮、相关对象 | 生成整改任务、冻结批次、创建设备点检 |
| 底部时间轴 | 展示计划、过程、审批、处理闭环 | 发现异常、完成分析、创建 CAPA、复检完成 |

## 3. 区域设计

### 3.1 顶部栏

职责：

- 全局搜索业务对象。
- 切换应用和角色上下文。
- 展示通知和待办数量。
- 进入账户中心。

搜索示例：

- 物料 `MAT-21`
- 工单 `WO-20260520-003`
- 设备 `EQ-03`
- 客户订单 `SO-7788`
- 供应商 `SUP-06`

### 3.2 左侧事件栏

职责：

- 展示当前角色需要关注的风险事件。
- 按严重度、状态、类型筛选。
- 支持快速切换事件。

示例：

```text
高风险
  3 号产线缺陷率异常
  MAT-21 物料库存低于安全线
  EQ-03 设备振动异常

处理中
  CAPA-20260520-001
  采购申请 PR-0088

我的任务
  2 个待审批
  1 个待补充资料
```

### 3.3 中央态势画布

职责：

- 展示当前事件的业务影响图。
- 支持点击对象节点查看详情。
- 支持高亮异常源头、受影响对象和已处理对象。

质量异常示例：

```text
供应商 SUP-06
   -> 物料 MAT-21
   -> 工单 WO-20260520-003
   -> 设备 EQ-03
   -> 质检 QC-8891
   -> 缺陷 D-102
   -> 客户订单 SO-7788
```

节点颜色约定：

| 状态 | 颜色 |
| --- | --- |
| 异常源头、风险事件 | 红色 |
| 受影响对象 | 橙色 |
| 普通关联对象 | 蓝色或灰色 |
| 已处理对象 | 绿色 |
| 未确认风险 | 黄色 |

### 3.4 右侧行动栏

职责：

- 展示 AI 分析，内容结构见 [AIP 风格智能层](aip-intelligence-layer.md)第 5.1 节。
- 展示处置方案。
- 展示资源和影响范围。
- 提供可执行业务动作。动作的定义和权限建议见 [Foundry 风格业务底座](foundry-foundation.md)第 5 节。

示例：

```text
AI 分析
  本次异常可能与 EQ-03 设备振动升高和 MAT-21 批次切换有关。

影响范围
  1 个工单
  1 个客户订单
  360 件同批库存

建议动作
  [生成质量整改任务]
  [冻结物料批次]
  [创建设备点检]
  [通知相关负责人]
```

交互要求：

- 动作按钮使用业务语义，如“生成整改任务”，不要只写“新增”。
- AI 面板必须给出证据、影响范围和建议动作，避免只输出泛泛文字。

### 3.5 底部时间轴

职责：

- 展示事件从发现到闭环的过程。
- 展示计划步骤和实际完成情况。
- 展示审批、评论和系统自动动作。

示例：

```text
09:18 发现异常
09:20 系统完成影响分析
09:25 质量经理确认风险
09:30 创建 CAPA 任务
10:10 设备点检完成
待完成 客户订单复检
```

## 4. 角色差异

同一个指挥台，应根据角色裁剪内容。角色的默认入口和整体职责见[角色工作台](role-workbench.md)第 3 节。

| 角色 | 左侧事件 | 中央画布 | 右侧动作 |
| --- | --- | --- | --- |
| 管理层 | 高风险事件、交付风险 | 全局影响图、客户订单影响 | 批示、催办、查看闭环 |
| 质量经理 | 质量异常、CAPA | 缺陷、质检、工单、物料关系 | 生成 CAPA、复检、冻结批次 |
| 生产主管 | 产线异常、工单风险 | 产线、设备、工单拓扑 | 暂停工单、调整计划 |
| 采购人员 | 供应商和物料风险 | 供应商、物料、库存关系 | 创建采购申请、供应商复核 |
| 设备工程师 | 设备预警、维修任务 | 设备、传感器、工单关系 | 接单、点检、维修反馈 |
| 审批人 | 待审批任务 | 关联对象摘要 | 同意、驳回、评论 |

## 5. 视觉风格

| 模式 | 使用场景 | 风格 |
| --- | --- | --- |
| 深色演示版 | 客户演示、大屏、管理层风险态势、智能运营中心 | 深色背景、蓝绿色关系线、红橙色风险强调、高对比信息卡、中央画布优先 |
| 浅色办公版 | 质量经理日常办公、审批人处理任务、管理员配置系统 | 保持 Ant Design 企业风格、信息密度更高、表单表格和审批评论更清晰、不追求大屏效果 |

建议“智能运营指挥台”使用深色，以增强态势感；“平台配置中心”和日常表单页面保持浅色企业风格，降低长期使用疲劳。

## 6. 与现有模块的对照

核对日期 2026-11-17。最接近本设计的现有页面是“质量影响与时间线”：路由 `/admin/quality-impact`，代码 `frontend/src/pages/QualityImpact`，页面标题“料号关系追踪台”，标注为实验功能，仅管理员可见。它采用浅色风格，没有深色演示版。

| UI 能力 | 状态 | 当前代码位置 | 后续建议 |
| --- | --- | --- | --- |
| 顶部全局搜索与通知 | 已实现 | 应用壳层 `frontend/src/App.tsx` 中的 `components/GlobalSearch`、`components/NotificationCenter`；后端 `api/search.py`、`api/notifications.py` | 搜索结果直达对象图谱 |
| 左侧风险事件队列 | 部分实现 | `QualityImpact` 顶部用下拉框切换质量事件，左栏为料号快捷入口；事件来自 `GET /quality/events`（`api/quality.py`）。没有跨质量、供应链、设备的统一风险事件视图 | 新增统一风险事件模型与队列 |
| 中央影响图谱 | 部分实现 | `QualityImpact` 的关系网络画布，数据来自 `GET /quality/events/{event_id}/impact` 与 `services/graph_service.py`；通用图谱探索在 `/data-center/objects?view=graph`（`pages/GraphExplorer`，基于 Cytoscape） | 嵌入业务详情页，不只做独立工具 |
| 右侧对象详情与动作 | 部分实现 | `QualityImpact` 右侧详情面板按节点类型显示动作按钮；“生成 CAPA”写入 `CAPA` 表，其余动作调用 `POST /quality/events/{event_id}/actions`，只返回演示结果 | 封装成真实业务动作并接入审批 |
| AI 行动栏 | 部分实现 | `QualityImpact` 的“AI 影响分析草稿”抽屉，调用 `POST /quality/events/{event_id}/ai-suggestion`，不调用大模型；全局 AI 面板 `components/AiChatWidget` 不读取当前事件上下文 | 改成上下文感知的 AI 面板 |
| 底部时间轴 | 部分实现 | `QualityImpact` 底部时间轴按节点和关系的时间戳展示追溯过程（`frontend/src/utils/qualityTimeline.ts`）；没有合并流程记录和操作日志 | 合并流程记录（`api/workflow.py`）与审计日志（`core/audit.py`） |
| 按角色裁剪 | 未实现 | 页面仅管理员可见，无角色差异 | 按第 4 节裁剪内容 |

指挥台的整体 MVP 顺序见[角色工作台](role-workbench.md)第 7 节。

## 7. 参考资料

- Gotham 类界面适合参考“事件队列、中央态势画布、右侧方案动作、底部时间轴”的指挥调度布局，但制造业系统应把军事地图替换为业务图谱、供应链路径、产线拓扑和订单影响链路。
