# 表单管理交互设计

状态：设计。表单列表与属性面板、字段结构面板、表单设计器和发布影响报告已经实现（见[表单](../../architecture/low-code/forms.md)），本文只保留尚未实现的表单管理交互目标。

表单的草稿、发布、停用、删除规则见[配置资产生命周期](configuration-lifecycle.md)，本文不重复。

## 1. 职责划分

目标是让“表单管理”只负责数据结构，“表单设计器”负责交互：

| 表单管理 | 表单设计器 |
| --- | --- |
| 名称、编码、绑定的业务对象、存储方式、负责人、说明 | 必填与即时提示、占位文字、宽度与分组 |
| 字段名称、编码、存储列、类型、长度与精度、是否允许为空、唯一、索引意图、默认值、关联目标 | 条件显示、联动、高级校验、选项来源细节、按钮布局、字段级权限 |
| 字段用途：列表显示、表单录入、可搜索 | |

“允许为空”是存储层意图，“必填”是运行期输入约束，两者应分开表达。当前实现中物理列一律允许为空，必填只通过规则在写入时校验，没有“允许为空”属性（未实现）。

## 2. 字段结构表

当前“字段结构”只显示字段名称、字段编码、类型、大小（字节）。目标是显示面向存储的完整信息（未实现）：

```text
字段名称  字段编码  存储列  类型  长度/精度  允许为空  唯一  索引  控件  列表  表单  搜索
```

其中“唯一”“索引”是意图声明。当前唯一校验由设计器规则实现，`searchable`、`sortable` 不建索引；把唯一或索引落成数据库约束需要单独的迁移与评审流程。

## 3. 表单管理操作

| 操作 | 含义 | 现状 |
| --- | --- | --- |
| 同步字段 | 从已有数据源、本体对象或已绑定的物理表导入或刷新字段定义 | 未实现 |
| 新增字段 | 创建字段元数据 | 已实现（“新增字段”） |
| 进入表单设计器 | 配置布局、校验、联动等交互 | 已实现 |
| 保存配置 | 保存表单基本信息与字段结构 | 已实现（按状态显示为“保存草稿”“保存变更”“保存配置”） |

表单基本信息中绑定业务对象或本体对象（未实现）：当前 `forms.model_id` 只指向旧版模型驱动的 `meta_models`，没有与本体对象关联的入口。

## 4. 发布前的结构影响摘要

发布前应汇总新增、修改、移除或隐藏的字段，必填与空值行为的变化，以及对已有记录的影响。当前发布影响报告已覆盖字段新增、类型兼容性、必填缺失、枚举收窄和归档字段仍有数据；面向物理表的数据库影响评审（涉及的表、列、索引、约束、迁移与回滚）尚未实现，目标见[配置资产生命周期](configuration-lifecycle.md#10-表单存储影响)。
