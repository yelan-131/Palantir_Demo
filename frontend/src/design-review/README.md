# ManuFoundry UI 三栏设计预览

此版本直接放在现有 React/Vite 前端中，通过独立 HTML 入口供设计评估。原有 main.tsx、App.tsx、业务页面和后端未修改。

## 本地启动

在 frontend 目录执行：

```sh
node node_modules/vite/bin/vite.js --config vite.review.config.ts
```

打开 http://127.0.0.1:13003/ui-review.html 。当前设备默认 node 无法运行时可使用随 Codex 提供的 Node 可执行文件。

## 与项目代码的对应

- `pages/Workflow/index.tsx`：直接复用原审批页面、搜索、来源过滤、详情抽屉、流程轨迹、通过和驳回逻辑。
- `services/api.ts`：工作台与审批仍通过 `wfListBusinessItems`、`wfApproveOrReject` 读取与处理数据；仅此预览入口安装 Axios 本地 adapter，未实现的接口拒绝调用，不访问后端。
- `PlatformFormField`：字段定义沿用 `field_name`、`field_type`、`control_type`、`required`、`visible_in_list`、`visible_in_form`、`enum_values` 和 `ui_config`。
- `components/FormWidgets/FieldControl.tsx`：填写页、设计画布和预览直接使用已有字段控件。
- `components/FormLayout` 和 `utils/formLayout.ts`：从同一份字段定义生成运行布局；设计发布后同步用于业务填写和列表。
- `theme/techWhite.ts`：复用字体、主题色和语义状态色；增加深色导航与更明确的内容层级。
- `config/navigation.ts`：复用 WORKFLOW_VIEWS；业务应用路径沿用项目的 `/program/...` 形式。

## 设计取舍

- 保留项目的三栏框架：56px 应用栏、208px 上下文菜单、独立滚动工作区。
- 应用栏切换区域；上下文菜单按应用展示对应页面和表单；菜单、面包屑与当前页面同步。
- 进入设计器继续保留中间菜单，只在用户手动收起时隐藏。
- 工作台移除独立统计卡片，数量并入待办视图标签；主体采用事项表格，底部保留紧凑常用表单入口。
- 事项突出来源表单、记录编号和审批节点；不添加业务接口中没有的优先级、截止时间或 KPI。
- 工作台移除重复应用卡片、最近申请侧栏和介绍文案；业务应用沿用左侧导航进入。
- 表单目录使用可搜索、可分类、可收藏的紧凑列表；业务应用展示关联记录，并按表单、状态与关键词筛选。
- 记录标题打开业务详情，来源表单打开数据列表，流程按钮打开原审批详情；操作入口按用途区分。
- 设计器在右侧工作区内提供画布与属性面板；宽屏时显示字段结构，较窄桌面保留“添加字段”入口，基础属性优先，高级字段设置折叠。
- 草稿与发布版本分开；保存后可恢复，离开未保存设计时提供保存提示。

## 数据与范围

数据是符合现有接口结构的本地示例。审批、申请、表单发布只影响此预览的 localStorage；没有绕过登录，也不写入正式数据库。独立演示键以 `mf-code-ui-review` 为前缀。

应用入口目前展示关联表单与记录，不替换正式生产看板、质量看板或业务权限引擎。设计发布检查为本地字段完整性检查，不执行后端 DDL、历史数据约束检查或真实部署。
